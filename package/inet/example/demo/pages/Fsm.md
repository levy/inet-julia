# State machines, generated

10BASE-T1S is defined in IEEE 802.3cg-2019 as state machines, and the standard
draws them as diagrams. Most ports read the diagram and write the code, and
from that moment the two can disagree — the diagram in the design document says
one thing, the `switch` statement says another, and only one of them runs.

Here the machine is a **document**, and the code is generated from it. There is
one machine, and everything else is a view of it: `MacFsm.jl` is output,
regenerated by `tool/generate_mac_fsm.jl`; the diagram `watch/mac_fsm.jl` draws
is a projection of the same document. Neither can drift, because neither is a
copy.

## The MAC, drawn

Here is that machine as a state diagram. Nothing was drawn by hand and nothing
was exported to get it here: the same document the code is generated from is
spliced into this page, and the projection that lays it out is the one
`watch/mac_fsm.jl` uses to light it up while a simulation runs.

```pred-ref
<<fsm("ethernet_csma_mac")>>
```

Six states. `IDLE` is where a MAC with nothing to do sits; carrier means
somebody else is talking, so it goes to `RECEIVING`, and a packet from above
sends it to `TRANSMITTING`. A collision detected mid-transmission goes to
`JAMMING` and then `BACKOFF`, and the inter-frame gap after a send is
`WAIT_IFG`.

Each edge is labelled with the trigger that fires it — an event like
`UPPER_PACKET`, or a timer as `timeout(backoff_timer)`. The **guards** are not
on the edges, deliberately: several of them are half a line of Julia each, and
fifteen of those overlap into something nobody can read at this size. They are
in the declaration immediately below, which is the same document, with room to
read them.

## The MAC, declared

This is the same machine as its declaration — six states, four events, four
timers, and the transitions between them. The diagram above is a projection of
exactly this:

```pred-ref
<<definition(file("../../../../tool/generate_mac_fsm.jl"), "ethernet_csma_mac_component")>>
```

`IDLE` on a carrier goes to `RECEIVING`, because someone else is talking; on a
packet from above it goes to `TRANSMITTING`. A collision sends it to `JAMMING`,
then `BACKOFF`, then back round. Guards and actions are Julia expressions
carried by the document rather than strings the generator pastes — `j("…")`
parses them, so a syntax error in a guard is found here rather than in the
generated file.

The declaration order of the states is load-bearing, and the comment above them
says why: the state's index is what gets recorded into the result vectors and
hashed into the network hash, so reordering the declarations would silently
change every recorded `state` series.

## PLCA, which is a different shape

```pred-ref
<<definition(file("../../../../tool/generate_plca_control_fsm.jl"), "plca_component")>>
```

The PLCA control machine is fourteen states, and it is *event-free*: §148.4.4.6
has no event dimension at all, so every transition is condition-only and the
machine is re-run until it settles. That is a genuinely different execution
model from the MAC's, and it is expressible in the same document type — which
is the argument for having a document type at all.

The PLCA data machine (nine more states) is declared in the same component, so
the two share variables and can fire into one another: the control machine's
`CS_COMMIT` entry drives the data machine, and the data machine's entries re-run
the control machine.

## What is and is not generated

Three of the protocol's four machines are documents: the MAC, PLCA control and
PLCA data. The **PHY is not** — it is a hand-written `@enum PhyFsmState` and a
transition function in `Phy.jl`. It is the smallest of the four and it was
ported directly; bringing it into the same form is the obvious next step and
would make the set complete.

## How the diagram got here

Worth a paragraph, because it is the one thing on this page that needed a new
piece of vocabulary.

Every other marker in this catalog names a **file**: `file` reads one,
`definition` reads a named definition out of one, and `realize` builds the
document a step file describes. A machine is in none of those — it is what
`ethernet_csma_mac_component()` returns. So the catalog grew one more marker,
`fsm("name")`, which resolves a name from a small table of machines. The table
is what keeps the marker language restricted: a marker still names data rather
than calling arbitrary Julia, and adding a machine is one entry rather than an
escape hatch.

Once the machine is on the page, drawing it is a dispatch entry. The renderer
already routes each kind of document to the projection that knows it — that is
how a simulation card became a widget with a working button — so a machine
routes to the diagram pipeline, and that pipeline is `watch/mac_fsm.jl`'s
rather than a copy of it.

## Watching it run

The diagram above is static. The same projection, in the watch demo, is not: a
monitor reads the MAC's live state once per slice and writes three integers
into the diagram, so a transition repaints the ring and re-strokes the edge
without re-running the graph layout.

That is one command away, and worth the command:

```
julia --project=watch watch/mac_fsm_sdl.jl
```

Bringing the live overlay onto this page needs a way for a page to say *which*
running simulation a diagram should follow — the card and the machine are two
separate embeds today, with nothing tying them together. That is the next piece
of shared machinery, not a missing line of content.
